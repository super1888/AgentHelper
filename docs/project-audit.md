# springAi 项目审查与工程化建议

## 1. 当前项目定位

该项目当前更适合作为 `Spring AI + Agent Framework` 的学习型多模块工程，已经具备以下基础能力：

- `agent`：Agent 创建与编排入口
- `core`：模型、工作流节点、通用配置
- `tools`：可供 Agent 调用的工具
- `hooks`：Hook 扩展点
- `interceptors`：拦截器扩展点
- `vectorStore`：向量存储与文档检索能力
- `common`：公共配置、工具类、常量
- `quickStart`：启动与样例验证模块

## 2. 本轮已完成优化

- 在 `common` 中补充了统一错误码、业务异常、全局异常处理、统一响应体
- 为后续数据库、权限、审计等能力预留统一异常出口
- 梳理出当前项目的工程化改造方向，便于后续分阶段优化

## 3. 当前主要问题

### 3.1 命名不统一

项目中仍存在一些明显的历史拼写问题：

- `emun` 应为 `enums`
- `domian` 应为 `domain`
- `CreatXxx` 应为 `CreateXxx`
- `toolFactory` / `templateFactory` 应采用大驼峰命名

### 3.2 学习样例与正式工程代码混在一起

`quickStart` 里的测试类承载了大量样例，适合学习，但不适合作为企业工程中的正式测试组织方式。

### 3.3 common 模块职责还可以继续强化

建议继续把以下基础能力收敛到 `common`：

- 通用错误码
- 统一响应对象
- 全局异常处理
- 通用常量
- 通用校验工具
- 通用 Web 层基础设施

## 4. 推荐的模块职责

- `agent`：只负责 Agent 创建、装配、工厂和 DTO
- `core`：只负责模型配置、工作流节点、底层能力封装
- `tools`：只负责 Tool 定义和 Tool 装配
- `hooks`：只负责 Hook 定义和 Hook 工厂
- `interceptors`：只负责 Interceptor 定义和工厂
- `vectorStore`：只负责向量存储、文档上传、文档检索
- `common`：只负责公共基础设施

## 5. 推荐的后续改造顺序

1. 先补齐本地 Maven 编译链路
2. 再分模块修正包名和类名拼写
3. 拆分 `quickStart` 大测试类
4. 为各模块补充 README 和示例
5. 再接数据库能力

## 6. 结论

当前项目的总体方向是正确的，已经有比较清晰的学习框架。若想进一步向企业工程靠拢，建议采用“先基础设施统一，再逐步命名治理和模块收敛”的方式推进，而不是一次性大改。
